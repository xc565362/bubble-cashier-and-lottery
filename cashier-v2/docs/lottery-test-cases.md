# 双活动抽奖与收银测试用例

本文件提供可复用的测试范围，不包含真实经营记录、顾客身份、券码或私有部署证据。2026-10-14 发布验收已完成本地回归 558 项（收银 352、此刻在地 81、山野有约 125）、更新与回滚测试 15 项，以及腾讯服务器已安装代码的隔离验收 7 项。它们是不同层次的证据，不能互相替代。

## 本地自动化

在三个项目各自目录运行 `npm test`。以下收银测试路径相对于 `cashier-system-sqb`。

| 场景 | 必须满足的结果 | 主要测试 |
| --- | --- | --- |
| 同用户并发、重试与最后一份库存 | 一人一次、不超发、重复请求回放结果、未中奖不能重抽 | 两个 H5 的测试；`tests/lottery-management.test.js` |
| 发券中断与恢复 | 结果先持久化；未完成时显示待发放；恢复不重复发券 | `tests/lottery-records-integration.test.js`、`tests/coupon-center.test.js` |
| 编辑商品、图片、概率及说明 | 配置校验和修订冲突保护生效；后续编辑不改变已发权益 | `tests/lottery-catalog.test.js`、`tests/scarf-management.test.js` |
| 记录和权威状态 | 区分中奖、未中奖、待发券；以券中心为准；不可用和旧记录显示未知 | `tests/lottery-records-backend.test.js`、`tests/lottery-records-integration.test.js` |
| 记录隐私与页面请求竞争 | 不返回原始 OpenID、券码或密钥；拒绝跨活动数据；旧响应不覆盖新页面 | `tests/lottery-records-ui.test.js`、`tests/lottery-records-bridge.test.js` |
| 在线登录和权限 | 未登录拒绝、Origin/CSRF 校验、员工与管理员权限隔离 | `tests/online-http.test.js` |
| 收银租约 | 只读查询无需租约；恢复、释放和核销等变更必须检查租约 | `tests/online-coupon-recovery.test.js` |
| 重复核销、重启和未知支付 | 只能成功占用一次；重启保留结果；未知支付不得释放权益或再次扣款 | `tests/coupon-center.test.js`、`tests/physical-coupon-center.test.js` |
| 微信登录票据 | 只信平台上下文；单次消费；绑定 AppID、活动和 Origin；拒绝过期与伪造票据 | 两个 H5 的登录测试 |

测试使用临时数据和受控支付上游。不得将自动测试指向真实收钱吧付款、经营库存或顾客凭证。

## 真实云端隔离验证

使用专用测试集合和无公众入口的 QA 函数，验证并发唯一性、最后库存、邀请码一次使用、未中奖持久化、票据单次消费及独立后续调用读回。已完成 9 项云端检查及独立读回；这一层外部券适配器明确采用模拟器，不能证明外部券服务已执行核销。

## 已安装券服务隔离验收

使用已发布代码、新建临时数据库、临时账户和密钥、localhost 临时端口，并隔离外部付款请求。已完成的 7 项检查为：

1. 券服务进程健康、身份与 Origin 边界、状态接口能力。
2. HTTP 发券幂等性，重试不会多发。
3. 权威状态接口脱敏且返回真实持久化状态。
4. 占用、准备及零元核销的完整状态转换。
5. 第二个独立 SQLite 连接读回核销结果。
6. 服务重启后结果保留，已核销凭证再次使用被拒绝。
7. 在线收银实际运行代码的静态资源、登录、只读查询和租约保护。

## 管理页面和发布验证

核对发布资源与清单哈希；正式接口仅做授权只读检查。管理员页面应正确展示历史状态、真实空列表、分页和筛选，切换筛选后重置页码。接口异常应明确报错，不回退为演示奖品或伪造历史。

更新器须验证目标身份、文件权限、备份及失败回滚；保留原有环境、账号、账本和密钥。SQLite 备份应包含 WAL 中的已提交数据，回滚程序时不得回退升级后的业务数据。

## 尚待完成的端到端验收

正式业务域名及小程序入口发布后，使用微信真机、专门测试活动和测试库存验证：微信进入 → 登录 → 新抽奖 → 发券 → 收银记录展示 → 核销 → 状态同步。另验会话过期重登、邀请码传递、重复扫码和网络中断恢复。

当前两个活动仍暂停，库存与活动时间需要业务核对。头巾正式记录为空，不能用空列表通过替代该活动的新凭证关联验收。受控间隔接口检查通过不代表赛事容量通过；快速探针曾遇到腾讯 429，仍需单独进行容量验证。真实收款、退款和现场设备不在本轮抽奖部署测试范围内。
