# 在线收银部署说明

初次在线迁移：2026-10-13。当前部署更新：2026-10-14，收银与券中心发布标识为 `20261014-b82dd53ca561`。本文件保留原路径供已有链接使用，详细历史经营数据和私有迁移证据不随源码公开。

## 运行结构

- `bubble-online.service` 以独立服务用户运行，监听 `127.0.0.1:5175`，提供管理员登录、共享账本、收银权限租约、活动管理和记录查询。
- `bubble-coupons.service` 提供共享券中心，监听 `127.0.0.1:3910`，管理发券、占用、核销和凭证状态。
- HTTPS 反向代理将 `/cashier/`、`/api/online/`、`/api/sqb/` 转发到在线收银，将 `/v1/`、`/healthz` 转发到券中心。
- 程序使用版本化目录 `/opt/bubble/cashier-online-<release>` 和 `/opt/bubble/coupon-center-<release>`；数据库与密钥位于独立的持久目录，不随前端重新构建覆盖。
- 两套 H5 及三个云函数部署在 CloudBase，抽奖记录由云端持久化，收银后台读取记录并关联券中心的权威状态。

管理员已完成首次设置，初始化入口关闭。密码不以明文保存，未登录访问 `/api/online/ledger` 应返回 401。活动管理只读页面无需取得收银租约；真实收银写入仍受租约保护。

## 配置与备份

账户、共享账本、支付连接配置、券库、CloudBase 集合和服务器加密密钥应分别纳入私有备份。不要将数据库、商户密钥、完整环境配置或导出文件提交 Git，也不要只备份静态页面。

升级前核对目标券中心身份和未决操作，保留原数据与服务配置备份。以版本化目录更新运行代码并准备回滚，保持既有券中心身份和已发凭证。旧维护脚本只适用于原有前提，运行前须审查当前目标及输入。

原本地网页资料已迁入在线共享账本；浏览器本地版和桌面版不会自动与云端双向同步。后续经营使用统一的在线入口。

## 基础检查

```sh
sudo systemctl status bubble-online.service bubble-coupons.service
sudo journalctl -u bubble-online.service --no-pager
sudo journalctl -u bubble-coupons.service --no-pager
```

检查券中心健康、未登录拒绝、管理员页面、活动记录及资源版本。日志仅供授权运维查看，不公开包含用户数据或配置的输出。测试收款服务时使用隔离环境；真实收退款需单独验收。
