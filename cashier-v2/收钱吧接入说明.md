# 收钱吧联调版 0.5.0（测试参数，不可直接投入正式营业）

## 当前状态

已按收钱吧官方轻 POS API 的顾客出码场景（scene=12）实现扫码收款、结果验签、自动查单、支付成功入账和扣库存、重复请求防护、重启后未完成支付恢复。
USB 小白盒需支持键盘输入（HID）模式，并在扫描结束后发送回车。软件不依赖收钱吧 Windows 客户端或 Windows 专有 SDK，因此同一套功能可用于 Windows、Mac 及本机网页。
2026-09-17 已接收技术支持的测试参数及配套密钥，并配置到本机网页版和 Windows 桌面版的独立支付目录。两端均已完成真实网关的签名查单和响应验签检测，网关对未创建的检测订单返回 ACQ.ORDER_NOT_FOUND。该检测不发起付款，不证明购买接口权限或完成商户验收。尚未进行真实付款、退款或小白盒实机扫码。

当前使用技术支持 15:34 发来的《moody收钱吧接口测试用参数信息｜20260917》附件中配套的测试私钥和响应验签公钥。此前自行生成的申请密钥已保留，不与这套测试参数混用。源码、安装包和 Mac 源码包均不包含真实私钥。

USB 盒子扫描顾客付款码对应“顾客出码/B扫C”，不是“顾客扫码/C扫B”。测试门店属于收钱吧的测试商户，不能理解为款项会结算到自己的正式商户。

## 正式营业前请向收钱吧确认

可把下面这段发给收钱吧商务或技术支持：

> @李志文，测试参数已配置，签名查单和响应验签通过，未发起真实付款。请确认测试门店的顾客出码 scene=12 支付权限、小额联调及当日退款的处理方式，并安排联调验收。请确认上线必验范围、正式商户参数及结算归属、收银机编号分配、原路退款和公网回调是否为必验项。也请确认 USB 小白盒的 HID 键盘模式及回车后缀。

注意：这里对接的是轻 POS，不是另一套 terminal_sn/terminal_key 的 Web API，不能混填两套参数。
本版支持导入技术支持提供的 PKCS1 / PKCS8 私钥、PEM / Base64 验签公钥，以及带密码的加密配置包迁移。普通经营备份不包含支付配置。不要把私钥贴进聊天或放进源码，不要用示例密钥替代。无需向本对话发送顾客付款码。

重要：文档明确说明不区分沙箱与生产环境，测试参数也在生产环境交易，会真实扣款。必须在授权和核对金额后才做联调，并按收钱吧要求当日退款。本版尚无原路退款功能，测试前需先确认退款处理渠道。

## 设置与使用

1. 更新前，在旧系统导出商品、订单 JSON 备份。
2. 打开新版，进入“商品 > 收钱吧设置”。
3. 本机两端已经配置测试参数，无需再次生成密钥。新电脑优先使用下文的加密配置迁移；手动配置时必须使用同一套参数对应的私钥和验签公钥。
4. 首次手动配置：填入 appid、品牌、门店、收银机编号、网关和验签公钥，选择“测试商户”，选择签名私钥文件并保存。原配置会自动备份。点“联网检测（不扣款）”，确认通过签名查单和验签。
5. USB 接上小白盒；点“USB 扫码检测”输入框，用普通商品条码测试。出现检测成功才说明软件收到了扫码内容；此操作不会付款。
6. 结算时点“收钱吧收款”，确认金额。测试参数每笔都需先勾选“我确认本笔为测试收款，可能真实扣款”，然后点付款码输入框，让顾客把微信/支付宝付款码对准盒子。扫描输入完后，回车将发起收款；若设备没有自动回车，可点“发起收款”。未勾选时不会发起测试支付。
7. 软件自动查询结果。只有收钱吧结果通过签名、订单号、币种、金额和支付流水校验后，才进入已收款流水并扣库存。

首次真实联调应由商户在收钱吧技术支持确认参数后自行操作，并核对软件订单、收钱吧商户后台和顾客账单。开发过程没有代用户进行真实小额扣款。

## 状态与异常

- 扫码收款发起前，可以关闭窗口返回购物车。
- 发起后，超时、网络错误或验签错误均不代表没扣钱。软件锁定本单，约每 3 秒查询，1 分钟后保留手动查单入口，不允许用叉号把未确认支付直接取消或重新收费。
- 重启后会恢复未核实支付，仍只查单，不会再次发送付款码。
- 收钱吧确认失败后，可以返回购物车重新结算，新一笔使用新订单号。
- “结果待核实”或部分支付不作为成功处理，需要联系收钱吧核对；未实现自动冲正，不能用删除本地记录绕过核实。
- 优惠券抵扣至 0 元时走“零元结算”，保留优惠记录；主动将全部商品免费出库时使用“0元出库”。两者均不会向收钱吧发送支付请求。
- 现有手工收款码功能继续保留；它仍依赖人工核实到账，不具备收钱吧自动查单能力。
- 取消订单和换货尚未接入收钱吧原路退款接口。需先在收钱吧处理实际退款或补款，再操作本地订单。软件会明确提示，不会把本地回退当成实际退款。

## 网页、Windows 和 Mac

Windows 打包后包含支付模块，不需要额外安装 Node.js 或收钱吧客户端。
Mac 使用源码中的 `bash build-mac.command` 生成 DMG，接口和界面与 Windows 共用；当前没有在 Mac 上实机验收。
两端的订单会记录支付时使用的测试/正式标识。切换为“正式商户”只改变本地标识，并不会把测试账号变成正式商户；必须同时换成技术支持开通的正式参数和对应密钥。

### 换电脑或迁移到 Mac

1. 在原电脑导出普通经营备份，用来迁移商品、库存和订单。
2. 进入“商品 > 收钱吧设置 > 加密配置迁移”，设定至少 12 个字符的独立密码，重复输入后点“导出加密配置”。
3. 将经营备份和 `.sqb.json` 加密配置包交给有权限的同事，密码通过另一渠道传递。配置包含签名权限，只能交给可信收银人员。
4. 新电脑安装新版，恢复经营备份。在收钱吧设置填“配置包密码”，点“导入加密配置”，选择配置包并确认，再运行联网检测。
5. 输入错误密码或篡改文件会导入失败，不覆盖原配置。有未完成支付时禁止替换或导出支付配置，需先在原机核实。
6. 换机迁移和多台同时收银不是一回事。多台同时使用时，先让技术支持分配各自的收银机编号，并在保存后重新检测。本版商品、库存和流水不跨设备同步。

网页开发版：

```bash
npm ci
npm run dev
```

正式本机网页服务：

```bash
npm ci
npm run build
npm start
```

默认打开 `http://localhost:5174/`。网页版支付管理只接受本机同源请求，不支持把纯静态网页直接丢到公网后收款，也没有把商户私钥打包进网页。手机和另一台电脑访问本机服务不在本次接入范围内。
开发版和正式本机网页服务共用 `.stall-cashier-sqb-web` 支付目录，不要同时启动。
网页与桌面软件仍各自保存经营数据及支付配置；不会自动跨设备同步。
付款和联网检测前通过 HTTPS 向 ipify 查询本机出口公网 IPv4，按规范以 X-Forwarded-For 上送收钱吧；该服务只接收普通 IP 查询，不接收商户密钥、订单或付款码。须能访问 ipify 和收钱吧网关。切勿使用会让两者走不同网络出口的分流代理。无法确定公网 IP 时不会发起新的付款，查单网络中断则保留待核实状态。

## 支付回传与通知

桌面版默认通过 HTTPS 主动查询收钱吧结果，实现自动回传，不需要公网服务器或内网穿透。
已实现可选通知处理入口：正式网页服务的 `POST /api/sqb/notify`。它校验收钱吧签名及订单金额，先持久保存结果，再返回 RSA 签名确认。重复通知不重复记账，未识别的通知不会误确认。
真正启用公网异步通知，还需固定 HTTPS 域名、反向代理到该入口，并由收钱吧配置；默认通知地址为空。本次没有部署公网通知服务，也没有安装或开放内网穿透。请不要把 localhost 填入通知地址。

## 数据保管

Windows/Mac 的商户私钥通过系统安全存储加密后保存在应用用户目录的 `sqb` 子目录；不会进入普通 JSON 经营备份，也不会进入安装包。
本机 Node 网页服务将配置、私钥及支付日志保存在用户目录 `.stall-cashier-sqb-web`，限制本机访问（Unix 文件权限 0600）；不要共享这个目录或上传网盘公开分享。
顾客付款码只用于本次请求，不写入订单、支付日志或备份；扫码检测完成后立即清空输入。
支付未核实前请不要清理浏览器数据、删除支付日志或换设备结账。同一应用安全迁移原密钥时无需重新生成；换成新密钥则需收钱吧更新公钥关系。加密配置包使用 scrypt 派生密钥和 AES-256-GCM 加密，密码不会进入安装包或经营备份。忘记密码需回原机重新导出。
设置中可导出脱敏诊断记录，含订单状态、金额和错误码，不含私钥、配置包密码或顾客付款码。它仍属于经营信息，只交给授权维护人员。诊断文件不是经营或支付账本的恢复备份。
