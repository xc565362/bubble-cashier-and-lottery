# H5 完整奖品管理 · 本地交付与启用说明

日期：2026-09-30。针对 `Bubble-H5-1.0.3-qr0922`，与独立的小红书头巾活动无关。

## 架构

收银台「抽奖管理」 → 本机签名桥 → 原 lottery 管理接口 → 原奖池的管理文档。

H5 → 登录网关 → 同一活动的奖池与中奖记录。实际抽奖始终在服务器事务中执行，网页只展示结果。新增奖项通过券中心建立独立履约活动，现金/实物凭证继续沿用原收银流程。

收银系统关闭后，已保存的云端活动仍可运行；必须是收银台成功保存到云端，H5 才会同步，离线未保存草稿不会生效。

## 一次性升级顺序

1. 核对当前线上代码、环境变量、活动日期及奖池状态，备份当天的订单、中奖记录、券、名额与管理审计。旧文档中的数量仅为历史快照，不能覆盖现有业务数据。
2. 在隔离环境先部署新版券中心，验证 `lottery-catalog-v1` 能力及新增管理员路由：`POST /v1/campaigns/lottery-provision`、`POST /v1/lottery/issue`、`POST /v1/lottery/coupons/detail`。原券活动和 API 保持兼容。
3. 同步升级原 `lottery` 云函数与 H5 登录网关的业务模块。两端必须指向同一云环境、同一 AppID 身份、同一 `campaign.id`、同一 entries/pools 集合，避免重复中奖和不同步。
4. 两个服务端都配置现有 `LOTTERY_MANAGEMENT_CENTER_JSON`：含券中心地址、身份、环境、管理令牌及原奖项映射。继续保留 `CASHIER_CENTER_JSON`、`PHYSICAL_CENTER_JSON`（active）、原管理员和管理签名密钥。任何令牌都不得复制到网页源码或 `dist`。
5. 发布新的 H5 静态文件，配置自有 HTTPS 网关；安装收银台 0.7.11 后读取现有连接。桌面与网页版数据目录分别保留，不能用空数据目录覆盖。原小程序旧前端若仍使用固定八奖项网格，也必须改为 H5 入口或升级为动态展示，才能开放新增奖项；不能让旧前端继续展示过时奖品。
6. 验证同账号仅一次、并发最后名额、旧凭证领取、新商品跨电脑匹配、真实扫码枪/微信 web-view，并核对活动有效期。原活动已结束，恢复按钮不会延长日期；新活动日期与历史活动迁移须另行确定。
7. 所有入口升级、配置核对和测试通过后，才开启完整奖项编辑。仅部署 H5、保留旧抽奖服务的组合不可用。H5 `state` 会同步/补发已有奖品对应的券，不能将它当作对生产完全无副作用的探测接口。

## 数据兼容

- 管理文档新增 catalog，同时保留原 revision、库存签名、幂等请求和审计。只在暂停时接受配置更新，冲突时拒绝覆盖另一台电脑的修改。
- 已保存 ID 的商品编码、类型、面额和门槛不可原位更换；替换需新 ID。retired 项留在后台历史中，但从 H5 的后续抽奖列表移除。
- 中奖记录保存奖品快照和服务器履约引用。之后的目录改名、改图或退役不改变旧中奖结果。
- 新奖项的券中心准备是幂等操作；网络或版本冲突后允许重试。若准备了一部分但最终配置未保存，H5 不会展示未发布目录，也不会据此发奖。
- public state/receipt 剔除内部商品信息与履约引用。客户端不能提交中奖结果、管理身份或领券面额。

## 图片和数量

初版通过 HTTPS 图片地址管理图片，自动带入商品已有的 HTTPS 图片。尚未提供本地照片上传到云端的按钮。无图/图片失败有明确默认示意。

当前目录最多保留 60 个奖项（包含历史退役项）。此功能编辑当前活动，不是无限多活动管理；需要换场次、换活动截止或清理旧场次时，应另建活动并保留历史核销。

## 打包与回退

修改前的代码分别备份在 `output/lottery-catalog-20260930/before`、`output/lottery-catalog-20260930-coupon/before` 和后端本轮备份目录。回退代码必须理解已发布 catalog 的格式；一旦启用新目录，不能回退到只认识原八个奖品 ID 的旧服务。回退任何版本都不能用旧数据库覆盖新订单和已中奖记录。

原始小程序 56 个前端文件未修改。此次云端部署和真实业务操作均为 0。
