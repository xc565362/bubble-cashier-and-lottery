# 网页异常收款修复（2026-09-26）

## 原因

收款请求出现网络异常后，原程序保留待核实交易，禁止关闭窗口以防重复收款。
但对收钱吧持续返回 `ACQ.ORDER_NOT_FOUND` 的情况，没有人工核对后的结束入口，导致一直被锁在收款窗口。
此错误仅表示当次查询未找到订单，不能单凭一次响应认定未扣款。

## 新处理入口

仅限普通收款：发起已满 2 分钟、多次验签通过的“订单不存在”查询覆盖至少 1 分钟、最近一次查询不超过 1 分钟，且从未取得有效远端订单或支付流水。
以上等待时间为本系统的保守核对门槛，不是收钱吧承诺的扣款超时时间。

1. 收银员核对顾客微信或支付宝账单，确认本笔未扣款。
2. 勾选“我已核对顾客账单，确认本笔未扣款”。
3. 点击“核实并结束本次收款”。后台必须再查一次，不能用旧查询结果直接结束。
4. 显示“已核对未扣款，本次收款已结束”后，点击“返回购物车”，或右上角关闭。

若最后查询发现支付成功，按已支付保存订单；查询断网、验签失败、返回其他错误或非终态时，仍保留待核实，不释放为失败。
已查到过远端订单的交易、部分支付、退款和换货补款不能使用此入口。

异常单以明确的人工核对原因保留在支付日志中，不删除原记录，不生成销售订单、不扣库存、不增加营业额，也不会自动发起第二次扣款或退款。
购物车恢复普通商品；已占用的中奖券按既有失败释放流程处理，需要重新扫码使用。
后续若收到有效的支付成功回调，会重新进入待对账，不会被之前的处理标记隐藏。

## 发布范围

本次修改 `payments/service.cjs`、新增 `payments/recovery.cjs`、修改 `src/sqb.jsx`，并增加服务端及隔离页面测试。
构建后的 `dist` 用于原网址 `http://localhost:5173/`，后台继续使用原支付数据目录和原商户密钥。
本次没有改变小程序、云端抽奖配置、兑奖截止时间，没有重新生成 Windows 安装包或 macOS 安装包。
使用旧安装包的同事不会自动获得本次修复。

## 操作注意

- 更新后台代码后需重启“启动收银网页版”，仅刷新网页不会更新后台。
- 不要清除浏览器数据，不要删除 `pendingPayment` 或支付日志来强行解锁。
- 已扣款或无法核实的订单不能勾选“未扣款”；应继续查单或联系收钱吧核对。
- 排查及测试均不得重新扫描顾客付款码发起试扣。

## 官方协议依据

- [轻 POS 响应通用定义](https://doc.shouqianba.com/litepos/公共定义/响应通用定义.html)：`ACQ.ORDER_NOT_FOUND` 表示订单不存在。
- [销售类结果查询](https://doc.shouqianba.com/litepos/查询/销售结果查询.html)：以原品牌、门店、收银机及商户订单号查询，并核对返回的订单与流水。

- 已目视检查桌面小屏及手机截图，无确认控件遮挡。测试没有真实扣款或退款。
