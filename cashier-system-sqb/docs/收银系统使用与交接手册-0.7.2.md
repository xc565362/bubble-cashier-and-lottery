# 01 接班与开摊检查

### 负责人先指定“唯一工作入口”

在交接时填好：营业电脑编号 `________`；使用方式（网页 / 桌面）`________`；Windows / Mac 用户名 `________`；浏览器及用户配置 `________`；日常启动入口 `________`；交接负责人 `________`。

网页版固定用原来的浏览器、原来的用户配置和完整地址。当前入口是 **http://localhost:5173/**。换浏览器、无痕窗口、系统用户或端口，可能看到另一套空白数据，不代表原数据已丢失。不要因此立即恢复旧备份覆盖。

### 每天开摊前逐项核对

1. 接电、联网，避免电脑休眠；连接 USB 扫码盒。需要扫描券二维码的设备必须支持二维码，不是所有一维扫码枪都支持。
2. 打开指定入口，检查商品数量、库存、近期订单，确认不是测试或空白实例。
3. 到 **商品 → 收钱吧设置**，确认正式商户、门店、收银机编号。不得擅自修改密钥、门店或收银机编号。
4. 点击 **联网检测（不扣款）**；它只验证网络和签名等，不代表已完成到账或结算验收。
5. 在 **USB 扫码检测** 扫一个商品码。建议扫码器使用键盘输入模式、英文输入状态，并带 Enter / Tab 结束符。此处不进行扣款。
6. 检查未完成支付、退款和券待同步记录，交清异常单，不能靠删除记录解除提示。
7. 检查商品售价、赠品规则有效期、库存和当日优惠活动；确认收款通知权限已允许。

### 谁能操作什么

| 角色 | 建议职责 |
| --- | --- |
| 当班收银员 | 正常销售、核对库存与赠品、日结、按授权处理退款 |
| 交接负责人 | 正式账号检查、备份与迁移、活动规则、异常金额复核 |
| 技术维护人 | 软件升级、Mac 打包、云端券服务、备份恢复演练 |

本版未实现独立员工登录、细分角色权限和员工操作审批。上述分工是管理制度，不是软件强制拦截；请用操作系统账号、锁屏和凭证保管控制访问。

> 营业前条件：电脑和扫码设备正常、网络可用、正式收钱吧配置正确、库存可信。抽奖券还要求正式券中心在线。软件不要求每台收银电脑自备固定公网 IP，但支付服务必须能检测实际公网 IPv4。

# 02 一笔正常收款

### 从加商品到完成订单

1. 点底部 **收银**。扫码器扫商品条码，或点商品加入购物车。支持已登记的不同格式条码，不限“69”开头；未知条码要先核对商品资料。
2. 核对商品、数量、售价、库存。修改数量后重新看合计。库存不足的商品不可继续销售，赠品也占库存。
3. 需要改单件商品优惠时，在该商品行输入 **优惠金额**。这里按“整行”减：2 件 × 20 元，输入优惠 5 元，整行应收 35 元，不是每件减 5 元。
4. 需要用券时先扫码券，再核对实收；每笔订单最多一张券。赠品二选一时先点 **选择赠品** 完成选择。
5. 点 **收钱吧收款**，再次看应收金额，勾选 **我确认本笔金额，将向顾客真实收款**。
6. 点 **发起收款**。看到 **等待顾客付款码** 后，再请顾客打开微信 / 支付宝付款码放到扫码盒上。输入焦点会自动进入顾客付款码区域，不需要先点击输入框。
7. 扫码器提交完整付款码后等待结果。无结束符时检查码已输入，再用界面提交按钮。不要把商品码、中奖券码当付款码提交。
8. 以系统核实 **收款成功** 并生成订单为准，再交货。系统按成功结果记录流水、处理库存，并尝试发送“收款成功 / 金额”通知。

### 哪个动作意味着真的收到了钱

| 看到的状态 | 正确做法 |
| --- | --- |
| 等待顾客付款码 | 尚未取得顾客支付结果，不交货 |
| 正在收款 / 支付待核实 | 等待或查询原订单，不再发起第二次扣款 |
| 核实收款成功，订单保存完成 | 核对金额，交付商品 |
| 顾客说扣款，但系统没成功 | 记下原单号，重新查询原单，找负责人核对 |
| 已支付但保存失败 | 使用“重试保存订单”，不要重新收钱 |

付款码尚未提交前退出收款，不会生成完成的收钱吧销售订单。付款已提交且结果不明时，系统会限制退出；不要强退、清缓存或重建订单。

> 系统通知只是辅助提醒，可能被浏览器或系统免打扰拦截。不要以“没弹通知”判断未收款，也不要只看顾客截图。当前没有保证可用的语音播报承诺。

# 03 优惠、赠品、挂单与零元

### 三种码，三个用途

| 扫的是什么 | 使用时机 | 结果 |
| --- | --- | --- |
| 商品条码 | 收银页添加商品 | 加商品或本地优惠券商品 |
| 抽奖中奖券二维码 | 加商品后、收款前 | 核验并占用唯一券，购物车抵扣 |
| 顾客微信 / 支付宝付款码 | 发起收款后 | 收钱吧对折后金额扣款 |

### 券怎么用

每单最多一张，本地优惠券商品与抽奖中奖券不能叠加。中奖券门槛按商品行优惠后的应收金额判断，抵扣不超过应收，不找零、不产生负订单。扫描中奖券是先占用，付款完成或确认零元结算后才核销；退款不会自动把券退回。

本地“优惠券”商品的同一码可用于不同订单，并非一次性中奖凭证。真实小程序券目前尚未上线，不能把商品里建一个通用优惠券条码当成已经完成抽奖联动。

### 赠品与挂单

在 **赠品** 页配置活动：主品只选售卖品，赠品只选赠品类型；支持多个主品 / 全选、多层赠品、二选一、叠加或不叠加，以及生效时间。赠品售价为 0，仍要维护库存。收银时核对自动加入的赠品和缺货提示，有选择按钮就先选好。

顾客暂时离开时，可点 **挂起**；回来后从 **挂单(n)** 恢复。挂单不是已成交订单，不代表库存已扣减，恢复后需重新核对库存。含抽奖中奖券的购物车需先移除券、释放占用，再挂起；回来后重新扫码。

### 下面三个动作不能混用

| 操作 | 含义和限制 |
| --- | --- |
| 0元出库 | 把本次购物车商品价格都置零，只记录出库。不是现金收款，更不是处理支付异常的办法 |
| 零元结算 | 优惠后本来为零，确认完成零元订单；不向收钱吧发起零元扣款。中奖券仍需正常核销 |
| 生成收款码 | 展示已上传的静态商户收款码，不等于收钱吧自动回传收款。必须在真实商户交易记录中核实收到钱，再点“确认收款” |

本版没有现金收款入口。正金额抽奖券订单必须走收钱吧核实收款，不接受静态码手工确认，也不能用 0 元出库绕过券流程。

# 04 退货、换货与取消订单

### 收钱吧订单：以真实资金结果为准

1. 到 **流水** 按日期找到原订单，核对收钱吧流水号、商品和实付金额。先确认是这笔，不用新建负价商品代替退款。
2. 点 **退货 / 换货**，选择退货或换货。填写退货数量和 **实际入库** 数量：收回但损坏不能再售的商品，可以退钱但不加回可售库存。
3. 赠品按实际收回情况勾选。没有收回的赠品不补库存；不能因退主品就默认全部赠品已回仓。
4. 换货时选择换入商品，核对新商品价格、库存与差价，填写原因。
5. 点 **核对退换货**，检查退 / 补金额、数量和实际入库，再勾选确认项。
6. 应退款时点 **确认原路退款**；应补款时先按该弹窗要求采集 **补款付款码**，再点 **确认补款**；无差价按界面确认完成。
7. 等待资金核实成功和订单保存后再认定完成。系统据结果处理库存和流水；结果未知时先查原单，不重复退款。

### 金额为什么不是吊牌价

退款按原订单实际支付金额及优惠分摊计算，不是直接退原价。赠品本身 0 元；整单用了券后，退其中一件也不应退超过它分摊到的实收。已核销中奖券不会因退款自动复活，补券需要负责人另行决定和记录。

### “取消订单”不一定真的退了钱

| 订单类别 | 取消 / 售后的注意事项 |
| --- | --- |
| 收钱吧真实支付订单 | 使用退换货流程处理真实原路退款；不要把本地删除理解为退款 |
| 静态码手工确认等非收钱吧订单 | “取消订单”只回退本地账务 / 库存，真实退款另行完成并留凭证 |
| 零元券订单 | 可按系统支持的取消流程恢复库存，已核销券不自动恢复；需要收费换货时重新开单 |

> 历史收钱吧订单售后会校验原门店、收银机编号和测试 / 正式模式。替换电脑时应沿用原配置与编号；不要在恢复之后随意改编号，否则历史退款也可能被阻止。

发现退款失败、结果不明或本地未保存，保留原订单号和错误内容交负责人。不要重复点多次，不手改库存来掩盖未决状态。

# 05 商品、导入与图片

### 商品建档

在 **商品 → 新增商品** 维护名称、条码、货品编码、分组、类型、原价、售价、库存和图片。类型区分 **售卖品 / 赠品 / 优惠券**：赠品售价为 0；优惠券填写抵扣金额。条码需唯一，既可包含字母，也可不是 69 开头。

### 批量导入步骤

1. 先 **导出备份**，再点 **下载模板**。在模板列名基础上填数据，不把标题行删掉或合并。
2. 条码、货品编码列先设为文本，保留开头的 0 和长数字，避免 Excel 自动变科学计数法。
3. 普通商品至少包含 **产品名称、条码、售价**。售价、原价、抵扣金额填写纯数字；库存为非负整数。
4. 可用列：产品名称、条码、货品编码、商品分组、商品类型、商品图片、原价、售价、库存数量、抵扣金额。
5. 保存 CSV / XLSX / XLS，在 **导入商品** 中选文件。首次先用少量样本，核对中文、条码、价格、类型、库存，再导完整表。
6. 导入后抽查同条码商品。已有条码会更新商品字段，包括库存；它不是“增加这么多库存”的入库单。

未填分组时归入“未分组”。出现“至少需要包含产品名称、条码、售价”时，先查首行列名、文件格式和编码；用当前下载的模板重存 XLSX 或 CSV UTF-8 后重试，不要靠乱改业务数据解决。

### 图片说明

上传 PNG 时，系统会合成白色背景并保存图片，适合透明底商品图。表格的 **商品图片** 列填写可访问的图片链接，不是把浮动图片贴在 Excel 单元格上；本机 C 盘路径也不是可跨电脑使用的图片地址。

通过上传保存的图片可随经营备份迁移。表格中的远程图片链接仍依赖原网站、链接权限和网络，不等于图片已离线保存。正式交接前在目标电脑抽查图片能否显示。

> 导入、改价、改库存前先备份；不要用过期库存表覆盖正在营业的商品。停止销售的商品不宜随意删除，先确认历史订单和售后需要。

# 06 流水、日结与备份

### 查看与导出

到 **流水** 选要查的日期，核对收入、订单、退款 / 换货等记录；不要只看“今日”推断过去营收。收钱吧订单对账使用收钱吧流水号，非收钱吧或旧订单可能使用本地 POS 单号。

导出的流水按商品子明细拆行，同一订单可能多行，并非重复收费。统计订单数要按订单号去重；商品数量 / 金额按相应明细列统计，不能把重复出现的订单级总额逐行相加。退款、差额调整按实际事件日期理解，不把原销售日与退款日混在一起。

### 收摊 / 交班顺序

1. 查看待支付、待退款、待保存和券待同步事项，逐单处理或记录交接，不能直接当作失败重收。
2. 核对本系统订单与收钱吧商户交易记录：流水号、实收、退款、交易状态。平台手续费、结算周期可能使银行到账不同于销售额，需另外核对结算记录。
3. 检查挂单和未结账购物车。普通未结账商品可先挂起；当前活动购物车不能当作已经备份。含中奖券的先按状态处理占用。
4. 导出当天流水用于复核，再到 **商品 → 导出备份** 保存经营备份。仅有 CSV 流水不能恢复整个系统。
5. 将备份存入受控的第二个位置，记录时间、版本、商户、收银机编号和负责人。完成后退出软件或关闭网页服务。

### 必须分开保管的三类资料

| 资料 | 内容 | 注意事项 |
| --- | --- | --- |
| 经营备份 | 商品、订单、挂单、赠品规则、收款码等经营状态；签名备份含相应支付 / 售后记录 | 不包含商户私钥、云端券库；不能当作随时倒带 |
| 收钱吧加密配置 | 正式商户参数、签名所需配置等 | 设置 12-200 字符迁移密码，配置包与密码分开保管 |
| 云端券备份 | 发券 / 占用 / 核销状态、服务签名材料等 | 由云端维护人一致性备份，经营备份不能替代 |

有未决资金、恢复事务或券占用 / 核销待同步时，系统可能禁止备份或恢复。先处理异常，不删除本地私有文件来绕过限制。旧备份也可能被拒绝回滚，以免把已经完成的收款重新当作未完成。

# 07 Windows 使用

### A. 使用已打包桌面软件

1. 从负责人获取 **cashier-release-0.7.2** 发行文件夹。日常只需二选一：便携版直接打开，或用 Setup 安装一次后从快捷方式启动。
2. 便携版：打开 windows 文件夹，双击 **摆摊收银台 0.7.2.exe**。安装版：运行 **摆摊收银台 Setup 0.7.2.exe**，按向导安装。
3. 不要每天运行安装器。桌面软件已带运行环境，普通使用不需要自行安装 Node.js。
4. 初次启动先检查商品与收钱吧配置；发行包不包含你的经营数据和私钥。按第 10 页迁移，再验收。

本机已有桌面快捷方式 **摆摊收银台 0.7.2**。程序未做商业代码签名，可能出现系统安全提示。只使用负责人确认来源的文件；被公司策略禁止或提示恶意 / 损坏时联系管理员，不关闭防护软件来强行运行。

### B. 使用本机网页版

这台已配置的电脑：双击桌面 **启动收银网页版**，在原浏览器打开 **http://localhost:5173/**。保持服务窗口运行；关闭它后网页即使还留在屏幕上，也不代表支付服务仍可用。

新 Windows 电脑需由维护人准备完整源码和 Node.js 24 LTS，在源码文件夹终端执行：

```powershell
npm ci
npm run build
npm start
```

之后仍需导入正式配置与经营备份。不要用纯静态网页、双击 dist/index.html 或只启动 Vite 预览代替支付服务。依赖安装 / 构建失败时交技术同事，不跳过报错开始营业。

### 安装位置不是数据备份

网页版支付配置常用目录：`C:\Users\admin\.stall-cashier-sqb-web`。

桌面版支付配置常用目录：`C:\Users\admin\AppData\Roaming\stall-cashier-system\sqb`。

以上是当前 Windows 用户的定位线索，不是需要发给所有同事的附件。桌面业务数据另由应用本地存储维护；便携版放在 U 盘并不代表业务数据都跟着 U 盘走。迁移用内置导出 / 导入，不公开复制私有目录。

Node.js 官方下载：[nodejs.org/en/download](https://nodejs.org/en/download)。选择 24 LTS，安装后重新打开终端。

# 08 Mac 使用：从零开始

### 先认识你拿到的文件

**cashier-system-0.7.2-mac-source.zip 是源码包，不是可双击安装的 DMG。** 当前没有 Mac 实机打包与验收结果。第一次最好由技术同事陪同完成；做成功后日常收银不需要重复这些构建步骤。

### 在 Mac 制作并安装桌面软件

1. 在“苹果菜单 → 关于本机”查看芯片信息，告诉维护人是 Apple 芯片还是 Intel。构建产物需匹配目标 Mac，不能假设一份包适用于所有架构。
2. 从 [Node.js 官方下载页](https://nodejs.org/en/download) 安装适合该 Mac 的 **Node.js 24 LTS**。不要从陌生下载站安装。
3. 双击源码 zip 解压，找到内含 package.json 和 build-mac.command 的 **cashier-system** 文件夹，放在固定位置。
4. 打开“启动台 → 其他 → 终端”。输入 `cd `，注意 cd 后有一个空格；把该文件夹从访达拖进终端，再按回车。
5. 输入以下命令并回车：

```bash
bash build-mac.command
```

6. 脚本会安装依赖、运行测试、生成 Mac 安装包并打开 release 文件夹。需联网；出现红色错误或脚本停止时截取错误交维护人，不把失败当成功。
7. 找到成功生成的 DMG，打开后按窗口提示把软件安装到“应用程序”，从应用程序启动。仍需执行第 10 页的配置和经营数据迁移。
8. 核对正式商户，测试扫码输入、布局和通知；由负责人亲自验收小额收款及退款后才能交班。

### Mac 安全提示与网页替代入口

本项目未提供已签名并公证的 Mac 发布包。仅对来源已核实、未篡改的软件，可在尝试打开后按 macOS 提示到“系统设置 → 隐私与安全性”查看是否允许打开；公司管理设备可能限制此操作。提示恶意软件或损坏时停止并联系维护人，不能按普通未验证开发者提示处理。

依据：[Apple《在 Mac 上安全地打开 App》](https://support.apple.com/zh-cn/102445)，核对日期 2026-09-20。不要关闭 Gatekeeper / SIP 来迁就安装。

如使用 Mac 本机网页版，在源码目录依次运行 `npm ci`、`npm run build`、`npm start`，保持终端运行，用固定浏览器访问 **http://localhost:5173/**。它和桌面版的数据不自动共用，迁移步骤仍然必需。

# 09 换电脑：完整迁移顺序

适用：Windows 换 Windows、Windows 换 Mac、Mac 换 Windows，以及同一电脑从网页版切到桌面版。下面是“替换原收银机”，不是两台同时使用。

### 旧电脑操作

1. 暂停营业，处理完所有待核实支付、退款、未保存订单、券占用和待同步事项。把需要保留的普通购物车挂起。
2. 记录软件版本、原工作入口、正式 appid / 品牌 / 门店、**原收银机编号**，以及最近一笔收钱吧流水号。
3. 进入 **商品 → 收钱吧设置 → 加密配置迁移**，自己设置 12-200 字符密码，两次一致，点 **导出加密配置**。保管好配置包和密码，分别传递。
4. 回到商品页 **导出备份**，保存最新经营备份。另导出需要的流水供前后对账。验证文件非空、时间正确。
5. 停止旧端收银，保留原电脑和备份直到新端验收通过。不要先删源代码、清浏览器数据或卸载旧数据目录。

### 新电脑操作：顺序不要颠倒

6. 安装 / 构建同版或兼容新版软件，确认新端没有需要保留的独立经营数据。有数据先停下来由负责人安排合并，不能直接覆盖。
7. **先导入收钱吧加密配置**：在设置页输入迁移密码，点“导入加密配置”，选原配置包。核对账号、门店、模式与原收银机编号完全一致。
8. **再恢复经营备份**：到商品页“恢复备份”。含收钱吧记录的签名备份校验商户、收银机、模式和签名密钥；不一致会拒绝恢复。
9. 如果已上线抽奖券，在新端连接同一正式券中心，为该设备获取新的券终端凭证。不要复制 coupon-connection.json 冒充新设备，也不要恢复云端旧库。
10. 检查商品数量、库存、图片、赠品规则、挂单、历史订单和原流水号。联网检测后由负责人亲自做小额收款 / 退款，核对真实商户和库存。
11. 验收签字后只启用新端。旧端保留离线备查，不再继续收银。

> 替换电脑要沿用原收银机编号，并在恢复后继续保留。改编号不仅会导致恢复失败，也可能让历史订单无法退款。不要重新生成 RSA 密钥来解决迁移问题。

经营备份和商户配置都含敏感业务信息，用受控传输或加密介质。软件发行包、聊天群公开附件中不应夹带私钥、迁移密码或真实券密钥。

# 10 不同电脑 / 系统怎么协作

### 先区分“替换”与“增加”

| 场景 | 正确做法 | 不能假设 |
| --- | --- | --- |
| 原电脑坏了，另一台接班 | 第 10 页全量迁移，保留原商户、密钥和收银机编号，旧端停用 | 换台电脑必须换 RSA 密钥 |
| 同电脑，网页换桌面 | 同样执行配置导入及经营备份恢复 | 同一台电脑就自动共用订单 |
| 增加另一台同时收银 | 单独终端编号、单独本地账本；负责人规划库存分配和售后归属 | 克隆原订单后两台可随意各卖各退 |
| 多台用同一云端券中心 | 各设备独立券凭证，券状态共享 | 券共享等于商品、库存、订单共享 |
| 手机要访问电脑收银 | 当前 localhost 服务仅本机可用；另行设计受控网络访问 | 手机上输入 localhost 会连到这台电脑 |

新增并行收银机不能照搬“替换电脑”全量订单后再改编号，历史订单会受到终端身份校验。可按受控商品主数据初始化，并单独配置终端；历史售后回原收银终端处理。统一库存、统一订单、跨终端售后需要额外开发，不是本版现成功能。

### 文件和文件夹分别是什么

| 文件 / 目录 | 角色 | 保管方式 |
| --- | --- | --- |
| cashier-system-sqb | 最新开发源码，后续修复 / 增加功能的基础 | 维护人备份，不当作无用旧版删除 |
| cashier-release-0.7.2 | 给同事分发的当前软件和文档 | 可分发，但不含经营数据和商户密钥 |
| Windows exe / Setup | 已编译软件 / 安装器 | 运行或安装，不能替代源码和备份 |
| mac-source.zip | Mac 构建用源码 | 在 Mac 生成适配安装包 |
| coupon-service-0.7.2.zip | 券中心后端服务代码 | 交技术同事部署，不是小程序安装包 |
| 经营备份 / 加密配置包 | 恢复业务 / 恢复商户配置 | 敏感资料，受控保管 |

### 升级也遵守同样原则

先解决未决交易，备份，再退出旧程序，最后用原工作入口与原数据配置启动新版。先核对数据再营业。不要运行与正式目录无关的测试预览，然后把“没有商品 / 没有配置”误认为升级丢失。

公司至少指定一名源码和备份保管人。源码、最新发行包、经营备份、加密配置、云端部署资料均需有负责人；只保留一个 exe 不能构成可维护的完整交接。

# 11 常见异常：先做什么

| 情况 | 先做什么 | 不要做什么 |
| --- | --- | --- |
| 顾客扣款了，系统未成功 | 保存原单号，重新查询支付结果；已付未保存则重试保存 | 重扫付款码再扣一次 |
| 原路退款结果未知 | 查同一退款记录，核对商户交易，交负责人处理 | 另外新发一笔退款 |
| 无法检测公网 IPv4 | 检查网络、代理或换手机热点，再检测；已有付款则先查原单 | 填虚假 IP、关闭证书校验 |
| 打开是空数据 | 查版本、启动入口、浏览器用户、端口和系统用户 | 立即清缓存或覆盖旧备份 |
| 导入说缺少必填列 | 用当前模板，查标题行、表格类型和 CSV 编码 | 把条码前导 0 删除 |
| 扫码未进入付款 | 先确认已点发起收款、正在等待付款码；查键盘模式和结束符 | 未就绪就反复扫顾客付款码 |
| 收款成功但没通知 | 查订单状态，再查浏览器通知权限、系统免打扰 | 当成没付款再收一次 |
| 中奖券无法使用 | 查正式云端连接、有效期、门槛、状态；等同步或联系负责人 | 用本地通用优惠券绕过核销 |
| 券显示使用中 / 待核实 | 看原交易，处理券占用 / 待同步；未知资金不强制释放 | 再给顾客补一张相同金额券 |
| 恢复提示身份不一致 | 核对原正式 / 测试模式、商户、收银机、加密配置 | 新生成密钥、手改备份内容 |

### 报障信息一次交齐

记录发生时间、电脑 / 系统、软件版本、网页地址或桌面入口、操作步骤、原订单号 / 收钱吧流水号、错误原文和截图。说明是否已真实扣款、是否退款以及顾客是否已拿货。

截图应遮挡顾客完整付款码、私钥、迁移密码和券后台密钥。不要把能再次使用的中奖券二维码公开发群；它属于持券凭证。

### 断网的边界

本地可查看部分已有资料，不意味着真实收款或云端中奖券可离线核验。券中心断网不会自动切换成本地券库。没有可靠支付结果时，应停止这笔交易并核实，不能凭“顾客手机显示过”擅自记账。
