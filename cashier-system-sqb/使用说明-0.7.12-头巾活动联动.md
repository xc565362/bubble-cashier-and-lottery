# 收银台 0.7.12 · 山野有约头巾活动

本版把独立的「山野有约」H5 接入收银系统。原抽奖与头巾活动在「抽奖」页分别管理，各自保留连接与中奖记录。

## 日常管理

1. 打开「抽奖 → 山野有约 · 关注抽头巾」。
2. 调整前填写原因、勾选核对，点击「暂停新抽奖」。
3. 选择核销要扣库存的商品，可修改奖品名称、HTTPS 图片地址、中奖概率、总名额、活动名称/地点和起止时间。
4. 保存后仍保持暂停。核对 H5 公示内容，再填写原因、确认并「开启新抽奖」。

初始规则是魔术头巾 200 份、每次中奖概率 50%、每个微信账号一次机会。未中奖也记录参与；名额用完后停止，不把尚未抽奖的人强行判为未中奖。活动时间尚未确定时可全部留空保存，正式活动保持关闭。

H5 首页、规则在可见且空闲时约 10 秒更新；领奖状态约 3 秒更新。只有成功保存到活动后台的配置才会生效。收银软件关闭后，已配置的云端活动可继续运行。

本活动保持单奖品模式，概率的剩余部分为未中奖。更换商品会建立新的奖品身份；旧中奖记录保留当时的奖品、图片、商品编码与领取期限。旧商品不要在尚有未领取中奖者时删除。

## 在收银台发放奖品

1. 工作人员核实小红书关注，在手机「现场工作台」生成一次性参与码，让顾客扫码抽奖。
2. 顾客中奖后出示 H5 的 16 位领奖二维码或条形码。
3. 收银员在「收银」扫描领取码。对应商品以免费赠品入单，数量固定 1 件。
4. 点击「零元结算」，核对订单后确认。看到核销成功再发放；商品库存扣一次，流水保留订单，顾客 H5 显示已领取。普通「0元出库」按钮用于其他出库，抽奖奖品要走「零元结算」。

重复核销、商品编码重复、商品缺货会被拒绝。如果出现网络中断或结果需核对，先恢复连接并按界面核对原订单，不要重新发奖。新接入的中奖凭证统一由收银券中心核销，手机工作台只查询并提示前往收银。

活动总名额是抽奖配额，本机商品库存是实际出库库存，分别管理。两台收银电脑的商品编码需要唯一对应；本机商品库存和经营账本不会因此自动变成多机共享账本。

## 一次性接入与上线

本地实现与正式上线是两个步骤。正式使用需要部署头巾服务和新版 H5，并让活动与收银台连接同一个券中心。

- 先备份当前经营数据与已配置连接，再使用新版安装包升级同一台电脑；不要用演示数据覆盖营业账本。
- 券中心需支持 `lottery-catalog-v1` 和 `physical-prize-v1`；无需为头巾另建一套收款商户。
- 头巾后端设置专用管理签名密钥、现有券中心身份/地址/管理凭证；详见头巾项目 `server/后端接入与上线边界.md`。凭证只存服务端和本机加密存储，不写入 H5。
- 「券管理」连接原云端券中心；「头巾活动连接」填写本活动 HTTPS 管理接口、活动编号 `scarf-xhs-50-v1` 与专用管理密钥。
- 在头巾管理中选择真实库存商品，核对活动日期、中奖概率和名额，再做微信真机扫码、并发核销和断网恢复验证，最后开放活动。

已有旧版独立核销凭证继续走原手机工作台，不会被转换为第二张收银券。新接入后产生的中奖凭证才进入收银流程。原活动历史记录、原收钱吧配置与密钥保持独立。

## 换电脑

经营备份、收钱吧加密配置、原抽奖管理连接、头巾管理连接分别迁移。头巾活动连接窗口提供独立「导出头巾连接 / 导入头巾连接」。券中心在新电脑重新连接；核对恢复后的商品 SKU/条码。

## 本地演示

双击「启动头巾收银联动演示.cmd」，打开 http://127.0.0.1:5209/ 。顶部可打开头巾 H5 或新测试参与者。所有服务及数据库均为隔离演示，外部请求被阻止，不产生真实收款、中奖或发放；重启会重建演示数据。

本次交付不自动替换已安装软件，也不自动发布云函数、小程序或正式 H5。正式日期仍待确定。
