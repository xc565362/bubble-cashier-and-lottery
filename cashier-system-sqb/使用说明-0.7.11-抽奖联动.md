# 收银台 0.7.11 · H5 奖品管理

现在可在「抽奖管理」维护 H5 奖品，无须反复修改网页代码。此版本已完成本地联动，正式云端尚未升级。

## 日常操作

1. 打开「抽奖」页，填写调整原因，勾选确认，点「暂停新抽奖」。
2. 点「新增奖项」增加实物或购物抵扣券。实物从现有商品中选择，每次核销扣 1 件库存；购物券填写面额和使用门槛。
3. 点「展示」改名称、手机短名和 HTTPS 图片地址。选择库存商品时会自动带入其已有的 HTTPS 图片；没有图片时使用原奖品插图或中性占位。
4. 要换成另一件商品或修改券面额，点「更换奖品」。系统会建立新奖项，原奖项停止后续抽取，旧中奖凭证保留原权益。
5. 填写总名额，选择「固定概率」或「按剩余名额」。固定概率合计必须为 100%，精确到 0.01%；按剩余名额时概率会随剩余数量变化。
6. 填写原因、勾选确认，点「保存配置」。配置保存后仍暂停抽奖，方便核对 H5。确认无误后再填写恢复原因、勾选确认，点「恢复新抽奖」。

H5 首页和规则页在可见且空闲时约每 10 秒更新，重新进入也会更新。抽奖动画、弹窗、离线和后台期间暂停轮询。领奖页继续约每 3 秒更新核销状态。

固定概率模式下，只要一个概率大于 0 的奖品名额耗尽，整个新抽奖暂停；补名额或改概率后再恢复，不会偷偷把概率转给其他奖品。总名额是抽奖配额，收银库存是现场实物，两者分别管理。已有奖品名额增加超过券中心上限时，先用「增加券发放上限」补足。

## 删除和历史中奖

「移除」只停止后续抽取，保留已中奖份数与历史记录。未保存的新奖项可以直接移除；已保存奖项的历史 ID 不删除。任何调整都不会把已中奖奖品换成另一件商品。

实物仍通过收银扫码、免费入单、完成零元结算后发放。换电脑使用时，该商品的 SKU 或条码必须唯一匹配当前电脑的商品；重复编码、缺货或找不到商品会阻止核销。购物券仍在付款成功后核销。

本版仍是原 1.0.3 活动的「每个账号 1 次、有名额时 100% 获奖」模式。固定概率指各奖项分别的概率，并没有新增「谢谢参与」奖项。独立的小红书头巾活动没有在本次改动中接入。

## 本地联动演示

运行 `npm run build -- --outDir output/lottery-catalog-20260930/preview-dist`，再运行 `npm run lottery:preview`，打开 http://127.0.0.1:5208/ 。也可使用同目录的「启动抽奖联动演示.cmd」。

演示使用临时数据库、临时身份和示例库存，拦截所有外部服务请求。顶部「打开 H5」可并排观察同步；「新测试参与者」用于重复体验抽奖。重新启动演示会重建演示奖池并重置该演示地址的浏览器账本，正式收银数据不受影响。不要把此地址用于现场或发给顾客。

## 正式启用

本次没有更新云端、替换已安装收银软件、延长原活动或操作真实抽奖、核销、支付数据。原活动的截止日期仍保持原配置。一次性升级要求和检查顺序见 `docs/H5完整奖品管理-0.7.11.md`。

若云端未升级，「新增奖项」会禁用并显示升级说明；原名额与概率管理仍可使用。不得仅更新网页后直接向旧云服务提交新奖项目录。
