# 收银系统 0.7.8 使用说明

更新日期：2026-09-26。本版支持同一商品正常售卖及活动赠送，共用一个条码、一个货品编码和一份库存，并包含网页异常收款恢复修复。

## 一个编码，既卖也送

1. 进入底部“商品”，找到原来的赠品，点击名称编辑。不要新建重复商品，也不要删除后重建。
2. 商品类型选择“售卖品”，输入正常销售的“售价”。
3. 勾选“可参与买赠”，显示“已启用”，点击“保存商品”。从原赠品改为售卖品时，会默认保留买赠资格。
4. 进入“赠品”，在规则的赠品选择框里选择该商品，名称后标注“可售可赠”。已有规则仍引用同一商品，不必重新绑定；仍需检查启用状态、生效时间及赠送数量。

- 平时扫商品条码或点击商品卡片：按售价加入。
- 买赠规则触发：另外加入“活动赠送 · 免费”行，价格为 0 元，不修改商品平时的售价。
- 同一单可同时购买和获赠同款，销售行和赠送行分开显示，共同扣减同一商品库存。二选一玩法同样支持可售可赠商品。
- 示例：库存 10 件，购买 1 件、活动赠送 1 件，完成订单后剩 8 件。不会为赠品另建库存。
- 保留“赠品”类型的商品仍为纯赠品，价格固定 0 元。不自动批量改变现有商品类型和价格。
- 仅勾选资格不代表自动送给所有订单；是否赠送仍由已启用的规则决定。原来的多主品、多层赠品、叠加开关和有效期保持原操作方式。
- 库存不足会提示；二选一中不足的选项不能选择。普通自动加赠若库存只够部分，提示实际加入数量，收银员需核对后结账。

## 导入、流水、退货

下载的新商品模板增加“可参与买赠”列，售卖品填“是”可同时作为活动赠品，填“否”关闭资格。已有模板不含这列时，会保留已有商品的资格。更新原商品请保留原条码，导入后核对售价和库存。

流水按销售行和赠送行拆分，同款可有相同编码；“商品类型”用于区分，“数量”包含实际赠送件数，“有效销售数量”不再把赠品计入销量。实物抽奖奖品仍保留独立发放数量列。旧订单记录不被重写，但重新导出的赠品销量按此口径计算。

退货按订单行区分售卖和赠送。赠品可退款金额为 0；库存只按实际入库数量回补，未实际收回的赠品不能勾选回库。挂单和经营备份保留商品资格及销售、赠送明细。

## 网页版更新

1. 营业结束或空闲时，先处理完待确认收付款，完成或挂起当前购物车，并导出经营备份。
2. 关闭原“启动收银网页版”启动窗口，重新双击桌面同名入口，然后刷新原浏览器的 http://localhost:5173/。
3. 若提示端口已占用，说明旧后台可能未退出，先联系维护人员核对，不要清空浏览器或改用新端口试营业。
4. 原浏览器、原地址、原经营数据和收钱吧配置保持使用。只刷新网页不能更新后台已加载的订单模块。

不要在未保存购物车、待收款或待退款状态直接重启。升级程序不等于商品已自动设为可售可赠，需按第一节编辑所需商品并设定实际售价。

## Windows 版

先完成待处理交易并导出经营备份，退出旧软件。

- 安装版：windows/摆摊收银台 Setup 0.7.8.exe。
- 便携版：windows/摆摊收银台 0.7.8.exe。

同一用户升级后先核对商品、库存和收钱吧商户。网页和桌面的经营数据不自动共用；从网页迁移或换电脑，仍需完整经营备份及加密连接配置，不要直接把同一份库存复制到多台机器同时营业。

## Mac 版

cashier-system-0.7.8-mac-source.zip 是同步修改后的源码构建包，不是现成 DMG。本次未在 Mac 真机编译和验收。

1. 在 Mac 解压，准备 Node.js 24 或更新版本（构建脚本要求）。
2. 打开“终端”，输入 `cd `，将解压后的 cashier-system 文件夹拖入终端，按回车。
3. 执行 `bash build-mac.command`，脚本将安装依赖、运行测试并生成安装包。
4. 构建成功后打开 release 文件夹中的 DMG 安装。未签名提示需由维护人员核对来源处理，不要关闭整机安全保护。
5. 如是换电脑，导入经营备份、加密收钱吧凭证及券中心和抽奖管理连接，核对商品库存、商户和四项实物绑定，再由操作员验收。

## 抽奖和收钱吧

本版不修改小程序代码、概率、奖品名额、云端活动截止或已有中奖码，不需要因此重新审核小程序或重新部署券服务。实物兑奖仍按原商品 ID 绑定，编辑售价和买赠资格不会重新建立绑定。不要更改已绑定奖品的名称、条码和货品编码，或删除重建商品。

当前项目约定的截止时间仍为北京时间 2026-09-27 18:00：同时停止新抽奖、实物领取和立减券抵扣。本次未重新连接云端改动配置。

收钱吧正式配置和原支付记录不被替换。网络异常待确认订单继续按原交易核对流程处理；仅在顾客明确未扣款，且系统满足订单不存在的核验条件时，才使用确认未收款的恢复入口。不得为了关闭窗口而虚报未付款。
