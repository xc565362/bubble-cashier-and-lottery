# 收银系统 0.7.10 使用说明

日期：2026-09-29。保留 0.7.9 的 45 字段流水查询，本次修复“已收款但当前浏览器无法保存订单，弹窗无法关闭”的问题。

## 这类异常如何处理

1. 收钱吧已经确认付款，但当前浏览器缺少原订单商品、库存不一致，或支付后台已确认过而当前浏览器没有原流水时，页面会明确提示经营数据待核对。
2. 点击右上角叉号，或“关闭弹窗，保留待核对”。这里只关闭弹窗，不取消付款、不补商品、不扣库存，也不清除待处理订单。
3. 页面上方保留“收款待核对”提示和订单号、金额。可以切换标签查看信息，在“流水”查询或导出当前浏览器已有记录；收银、商品和账务修改保持锁定。
4. 点击“查看待核对收款”可重新打开。核对经营数据后再决定是否重试；不要连续点击重试，不能靠新建同名商品代替原商品。
5. 正常保存待核对状态后，刷新页面、网络重连或自动对账不会强行弹出同一收款窗口。若本机存储空间不足而无法保留状态，系统会明确报错，不会假装已经保存。

“重试保存订单”仍只查询既有支付结果和尝试保存，不会重新发起扣款。后台已有确认标记、当前浏览器没有原订单时，禁止自动重新入账；即便碰巧有同样商品和库存，也不能重复扣库存。

付款结果仍不明确的交易，继续使用原有核实流程，不能通过本功能强制结束或认定未扣款。本次没有放宽未确认支付、退款或优惠券核销的保护。

## 浏览器数据隔离

Codex 内置浏览器、Chrome、Edge 和桌面版不是同一套本地经营账本，即使网页地址相同也不能假定商品和流水相同。本机网页版可能共用支付后台，但浏览器保存的经营数据分别独立。

正式营业继续使用原来保存着完整商品和流水的浏览器。看到别的浏览器缺数据时，不要清空原浏览器，不要直接把备份导入多个浏览器同时营业。已确认的旧收款在另一浏览器出现，不等于新发生了一笔收款。

## 更新

- 网页版：完成或挂起普通浏览器当前购物车后，刷新原地址 http://localhost:5173/。卡住的 Codex 页面也需要刷新加载新界面，然后点击“关闭弹窗，保留待核对”。本次没有修改支付后台，无需为此重配收钱吧。
- Windows：完成待处理交易并备份，退出旧软件，使用 windows/摆摊收银台 Setup 0.7.10.exe，或便携版 windows/摆摊收银台 0.7.10.exe。同一系统用户更新后先核对原数据。
- Mac：cashier-system-0.7.10-mac-source.zip 是同步源码包，不是现成 DMG。在 Mac 解压，准备 Node.js 24 或更新版本，进入目录执行 `bash build-mac.command` 构建。未在 Mac 真机验证。

本次不改变收钱吧商户参数，不删除支付记录，不修改普通浏览器原商品和历史流水，不调整小程序、券服务器或活动时间。
