# 动态抽奖券接口

这些接口仅供经过管理凭证认证的可信服务端调用；浏览器 Origin 请求和普通收银/抽奖凭证不能调用。管理凭证不得进入 H5、收银页面或奖项数据。

- `POST /v1/campaigns/lottery-provision`：按外部活动 `campaignId` 与 `prize.id` 幂等准备券活动，返回 `{campaign}`。新实物包含 `product: {id, name, sku, barcode}`，数量固定为一件，SKU/条码至少一个非空。现金 `amount` 单位为元，最多两位小数；`minimumCents` 单位为分。
- `POST /v1/lottery/issue`：`{requestId, campaignId, owner, awardId, code?}`，其中 `campaignId` 为已准备的券中心活动 ID，实物 code 为原中奖记录的 16 位大写十六进制码。
- `POST /v1/lottery/coupons/detail`：`{campaignId, id, owner}`，同时验证活动、领取人及发放来源。

同奖项 ID 不允许更改商品代码、类型、券额、门槛或使用期限；更换权益须创建新奖项 ID。准备接口复用已有活动时不覆盖名称、容量或历史记录。提高容量须通过原有、带原因和幂等请求 ID 的扩容接口。名额为零的新奖项按券上限一张准备，抽奖池仍应保持零名额。

实物券保留发行时商品快照。本机商品 ID 可以不同；收银按可信券快照中的 SKU/条码匹配当前商品目录，若代码对应多个商品、代码互相冲突或库存不足则拒绝并释放占用。核销必须进入收银订单、数量一件、价格零元，完成订单后扣一次库存。

## 请求限流

先验证凭证，再解析受大小限制的 JSON，最后扣取请求额度。

- 原管理请求保持每分钟 180 次。
- 已认证管理身份发起的动态发券及详情请求，按 `owner` 合计每分钟 60 次，两个接口和不同活动共享同一领取人的计数。
- 上述动态请求总计每分钟默认 6000 次，通过服务端环境变量 `COUPON_CATALOG_RATE_LIMIT` 配置为 1 至 1000000 的整数。它与原管理额度分离；无效领取人也计入总额度。
- `owner` 为 1 至 120 位字母、数字及 `_.:-`，首位必须为字母或数字。云端接入使用不可反推微信身份的哈希值。

当前计数保存在券服务进程内，每分钟重置；多实例部署须由共同入口提供等价的共享限流，不能把每个实例的额度误当成整个集群的总额。身份、券归属和幂等校验仍由数据库执行，限流不替代这些校验。

本次仅完成本地实现与隔离测试，未连接、部署或修改真实券中心。
