# 收银台 0.7.13 · 此刻在地与山野有约

在「抽奖」中选择「此刻在地」或「山野有约 · 关注抽头巾」。两个活动分别管理，共用「券管理」连接的同一个云端券中心核销。

## 配置奖品

此刻在地：支持新增/移除奖项、更换库存商品、修改名称和图片、调整各奖项名额及概率；支持实物奖品和金额券。先暂停抽奖，再编辑和保存，确认后恢复。

山野有约：保持单奖品九宫格。4 格奖品、4 格谢谢惠顾，中奖概率由后台配置，不按格子重新计算。默认魔术头巾 200 份、50%；可更换商品、名称和图片，调整概率、名额、活动名称/地点及日期。先暂停，再修改保存，最后开启。

成功保存后，两个 H5 的首页及规则页会在可见空闲时约 10 秒内更新。已中奖凭证保留原来的奖品及权益；移除或更换奖项不会重新抽奖。各活动的调整记录可在相应管理页查看。

## 编辑 H5 活动说明

两个活动均支持在「抽奖」管理页编辑「活动说明正文」。先填写原因并暂停新抽奖，再填写正文、核对文字预览，填写本次调整原因并勾选确认，点击「保存配置」或「保存头巾活动」。核对 H5 后再恢复抽奖。

正文支持最多 5000 个字符的多行纯文本，保留换行，不执行 HTML。清空并保存会恢复原有默认说明。奖品、概率和日期仍从实际活动配置自动显示，无需重复写入正文。此刻在地保留单独的隐私与帮助说明；两页均保留工作人员入口。

保存后的文字独立属于所选活动，不改变已有中奖凭证。在线 H5 的规则/说明页在可见空闲时约 10 秒内更新，也可重新打开页面查看。单独启动的隔离 H5 演示不连接正式收银配置；联动验证请使用双活动演示入口。

此功能需同时更新收银端、两套 H5 页面及对应抽奖服务。管理接口通过 `rules-text-v1` 标识支持情况；旧服务会显示升级提示并禁止编辑正文，其他奖品配置仍可按原能力保存。更新程序本身不会自动发布云端或修改活动说明。

## 同一收银台核销

两个活动管理页都有「去收银核销」。也可直接打开「收银」扫码，无须先选择活动。

- 实物奖品：扫描顾客 H5 的领奖二维码或条形码 → 对应商品免费入单 → 点击「零元结算」并确认 → 成功后发放。记录订单，并扣减本机商品库存一次。
- 金额券：扫描顾客券码，按券规则在购物结算时抵扣。金额券不是免费实物，不能凭它直接出库。
- 重复、过期、已核销凭证不能再次领取；网络结果不明时先核对原订单，不要重新发放。H5 领取状态约 3 秒刷新，核销完成后原凭证失效。

每台电脑的 SKU/条码必须唯一对应同一个真实商品。活动名额与实物库存分别管理；本机库存和流水没有因此自动变成多机共享数据。

## 正式接入

本地双活动联动已经实现；正式使用仍需要部署并填写实际服务连接。本次没有替换正在使用的收银软件、修改收钱吧配置或发布线上活动。

1. 备份经营数据和已加密的连接配置，再安装 0.7.13。沿用现有券中心，不需要另开收款商户。
2. 升级券中心至支持 `physical-prize-v1` 和 `lottery-catalog-v1` 的版本；在「券管理」连接这个中心。
3. 此刻在地：部署交付的 `lottery-backend` 管理服务及 H5 网关；两者须使用同一活动和云数据库。「此刻在地连接」填 HTTPS 管理接口、活动编号 `bubble-race-2026-500` 及该活动管理签名密钥。
4. 山野有约：部署头巾 H5 项目中的服务，设置同一券中心及独立管理密钥。「头巾活动连接」填以 `/api/scarf-management` 结尾的 HTTPS 管理接口、活动编号 `scarf-xhs-50-v1` 和对应密钥。
5. 部署两套 H5，各自的 `runtime-config.js` 填对应公开网关地址。管理密钥和券中心令牌只留在后端及收银端加密存储，不能写进 H5。
6. 两个管理页都应显示「核销已接入相同券中心」。旧版此刻在地服务如果缺少身份核验字段，会提示升级；奖池仍可查看、暂停和配置。
7. 配置真实商品和活动时间，再验证手机参与、收银核销及断网恢复后开放活动。

此刻在地原配置的活动日期已过期，本次没有擅自延长。山野有约正式日期仍待确定。演示中的临时日期不属于正式配置。

山野有约接入收银之前已发出的旧 `legacy` 凭证继续使用原手机工作台核销；新凭证才进收银券中心，不会把旧奖重新发成另一张券。

## 同时体验两个活动

双击「启动双活动收银演示.cmd」，或运行 `npm run activities:preview`（首次先构建预览）。打开 `http://127.0.0.1:5211/`。

顶部有此刻在地和山野有约 H5 的独立入口；两个管理连接同时可用，共享一个临时券中心及示例商品账本。所有数据仅为隔离演示，不连接真实收款服务；重启会重建测试数据。
