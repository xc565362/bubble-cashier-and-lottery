# Bubble 活动 H5 · 1.0.3-qr0922

这是从本机「小程序前端-二维码版」迁出的 H5 工程。保留原活动橙色风格、九宫格奖品、领奖凭证和规则内容，原小程序文件未被覆盖。

2026-09-30 更新至 `h5.2`：已完成与收银台 0.7.11 的完整奖品管理联动代码。首页和规则页约每 10 秒自动读取云端奖项，可随收银端的增删、改名、换图和概率变化。8 项保持九宫格，其余数量自适应排版。历史中奖凭证保留原奖品。正式服务尚未部署升级。

联动演示入口为 http://127.0.0.1:5208/ （先在收银工程运行「启动抽奖联动演示.cmd」），详情见收银工程 `使用说明-0.7.11-抽奖联动.md`。下方 5188 仍是独立页面预览，使用内置演示数据，不会读取收银端修改。

## 先看效果

双击 `启动本地预览.cmd`，然后打开 http://127.0.0.1:5188/ 。也可在此文件夹的终端执行 `npm start`。需要 Node.js 20 或更高版本；本机已有可用 Node.js。

预览包括：

- 抽奖首页：内置预览为八种奖品；正式与联动模式从服务端读取动态奖项、中奖弹窗和已参与状态。
- 我的奖品：二维码、条形码切换、完整码复制、使用状态刷新。
- 活动规则：奖品、参与说明、活动时间、隐私说明。
- 工作人员入口：查询凭证、摄像头扫码能力检测、手工输入或扫码枪输入。金额券及实物奖品均按现有收银流程办理；实物需收银扫码免费入单后发放。

页面底部的「预览设置」可切换实物、购物券、结算中、已核销、过期、断网等状态。展开设置时暂停自动刷新，方便操作；收起后恢复刷新。重置只清理当前标签页的演示数据。

**本地预览不连接正式奖池，展示的码不能抵扣或领取。** 地址只在这台电脑上可用，不能直接发给手机或嵌入线上小程序。首次演示抽奖固定给出 10 元券，避免把演示当作正式概率验证。

## 正式接入还需要什么

1. 一个已配置好 HTTPS 的网页地址及该小程序的业务域名验证。
2. 在测试云环境配置随附 H5 登录网关，核对当前线上后台逻辑，再验证微信登录、同一用户中奖记录、收银核销和并发防重。
3. 将 `public/runtime-config.js` 的 `apiBase` 改为测试通过的网关地址，保持 `mode:'production'`，执行 `npm run build`。只将 `dist/` 上传到网页托管目录。
4. 取得要增加入口的 1.0.5 项目源码，按 `integrations/接入1.0.5说明.md` 接入随附 `web-view` 宿主页，然后完成真机测试与小程序审核发布。

后端环境变量、接口与操作边界详见 `server/后端接入与上线边界.md`。小程序 AppSecret、签名密钥、收银服务密钥只能配置在服务端，不能放到 `public/` 或 `dist/`。

本次生成了接入文件，没有部署云函数、上传小程序、修改正式数据库或执行真实抽奖核销。1.0.5 尚未实际增加入口。

## 给维护者

| 路径 | 用途 |
|---|---|
| `public/` | 可编辑网页源码与原始奖品素材 |
| `public/runtime-config.js` | 正式网页接口配置，默认没有接口地址 |
| `scripts/preview.mjs` | 仅本机的隔离演示服务器 |
| `dist/` | 构建后的正式静态文件，不含演示数据模块 |
| `server/cloudfunctions/bubble-h5-gateway/` | 独立云函数网关，默认关闭 |
| `integrations/miniprogram/pages/bubble-h5/` | 给现有小程序增加的宿主页 |
| `tests/` | 本地自动化回归测试，无真实云端请求 |
| `验证记录.md` | 已验证范围与尚未验证项目 |

本地预览、构建不需要安装第三方依赖。运行自动化测试需先执行 `npm ci`，再执行 `npm test`。部署云函数时，在该函数目录单独安装其生产依赖。

条形码需要足够的屏幕像素宽度。空间不足时会提示使用二维码或横屏，避免展示无法可靠扫描的压缩条形码。真机相机、微信 web-view、收银扫码枪仍需联合验收。
