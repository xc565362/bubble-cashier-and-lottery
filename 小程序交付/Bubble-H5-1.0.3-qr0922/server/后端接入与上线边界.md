# H5 登录网关与原抽奖数据衔接

提供独立云函数 `cloudfunctions/bubble-h5-gateway`，不替换原 `lottery` 云函数。默认未启用，未安装依赖、未部署、未访问生产接口或数据库。

## 已确认的业务来源

二维码前端 `1.0.3-qr0922` 的 `utils/api.js` 调用原 `lottery` 云函数；开发演示使用本地 demo。原云函数从 `cloud.getWXContext().OPENID` 取得可信身份，不能把浏览器传入的 OpenID 当作登录依据。

1.0.2 ZIP 的云函数是旧快照。当前本机 `cashier-system-sqb/lottery-backend` 已增加动态库存管理与实物券中心衔接。2026-09-30 增加完整奖项目录管理后，本网关共复制该目录的 12 个共享业务模块到 `vendor/lottery`，哈希见 `source-manifest.json`。**这仅证明本地代码来源，尚未与线上当前部署代码和环境变量比较，不代表可直接接入现网。**

完整奖品管理必须同时升级原 lottery 云函数、H5 网关和券中心，否则旧函数不能理解新增的奖项 ID。原小程序固定网格也须改成 H5 入口或动态奖品展示。收银台版本为 0.7.11；完整部署说明在收银工程 `docs/H5完整奖品管理-0.7.11.md`。

原业务动作包括 `state/draw/identity/lookup/redeem/activityCode`，还有奖池初始化、实物迁移与管理 HTTP 入口。H5 白名单仅开放前六项；不导出初始化、实物迁移或奖池管理接口。管理员来自服务端 `LOTTERY_ADMIN_OPENIDS`。本网关强制要求实物中心开启，全部实物奖品都必须在收银系统扫码、免费入单、完成核销后发放；H5 不提供直接完成实物兑奖的通道。`redeem` 对实物返回 `POS_REQUIRED`，保留原后端拒绝逻辑，不恢复旧直接核销流程。

适配器为 `state.entry`、`draw`、`lookup` 的实物回执统一增加 `requiresPos:true`，HTTP 网关保留该字段。该标记说明领取方式，与 `pending/redeemed/expired/unavailable` 状态分开；已核销回执也保留标记。前端收到它后应展示“请到收银台扫码核销”，不能显示能直接完成兑奖的按钮。购物抵扣券继续按原 `checkoutCoupon:true` 流程在收银系统付款结算后核销。

`state` 也可能补发尚未落券的中奖权益，并非绝对只读接口。因此联调前须接入测试环境，不能用生产 state 请求当作无副作用探测。

## 接口契约

默认 API 根路径 `/api/bubble-h5`，可用 `H5_API_BASE_PATH` 修改，H5 的 apiBase 必须与之匹配。

| 请求 | 输入 | 输出 |
|---|---|---|
| POST /session | `{code}`，同 AppID 原生 wx.login code | `{ok:true,data:{token,expiresAt}}`，expiresAt 为毫秒时间戳 |
| POST /call | `Authorization: Bearer ...`，`{action,payload}` | `{ok:true,data}` 或 `{ok:false,code,message}` |
| OPTIONS | 精确匹配的 Origin | 204 CORS 预检 |

`payload` 对 state/draw/identity/activityCode 必须为空对象；lookup/redeem 只接受字符串 `code`。禁止客户端上传 openId、isAdmin、entryId、奖品、剩余库存等身份和业务决策字段。此工程的正式配置锁定来源 AppID `wx3cfec968f30fb6c1`，防止误用第二个 AppID 造成用户标识变化和重复发奖。网关 token 绑定 AppID、Origin 与有效期；HMAC 签名密钥只在服务端。令牌载荷可被解码，不能把 token 当作保密容器，H5 不得写入 URL 或日志。

接口要求 `application/json`，8 KB 请求上限，无缓存。code2Session 请求限定微信 HTTPS 接口、8 秒超时、禁止重定向，响应中的 session_key 不返回浏览器、不入日志。错误不会回显上游 URL、凭据或内部异常。签名失效/过期时无业务调用。CORS 只是浏览器限制，真正鉴权依赖微信 code 与服务端令牌。

## 部署所需配置

1. 上线维护者先将 `vendor/lottery` 与当前生产 `lottery` 云函数比较，确认活动配置、动态库存管理、券中心映射、实物中心切换状态和收银系统协议仍一致。不要复制覆盖现有数据库，也不要初始化或重置奖池。比较后再显式设置 `H5_BACKEND_REVIEWED=1`。
2. 在相同云环境创建一个新云函数 `bubble-h5-gateway`，Node.js 18 或更高，使用该目录自带的 `wx-server-sdk@4.0.2` 依赖和 `index.main` 入口。使用事件型云函数的 HTTP 网关，不是另一种 `context.httpContext` HTTP Functions Framework。
3. 在新函数的服务端环境变量配置 `environment.example.txt` 列出的项目。`H5_APP_SECRET` 为该 AppID 的秘密值；`H5_TOKEN_SECRET` 需独立生成 32 字节随机数，使用 64 位十六进制值。不要在网页、源码仓库或终端输出这些实际值。
4. 由管理员从已核对的生产配置安全设置 `CASHIER_CENTER_JSON`、`PHYSICAL_CENTER_JSON`、`LOTTERY_ADMIN_OPENIDS`，不得使用演示假值。物理券配置必须是 `stage=active`；缺失即关闭，不退回旧核销逻辑。完整奖项目录还需要服务端 `LOTTERY_MANAGEMENT_CENTER_JSON` 中的券中心身份、环境、管理令牌和原奖项映射；它只供新奖品的服务器履约调用，不能放入前端。H5 网关不需要 `LOTTERY_MANAGEMENT_KEY`，也不暴露原管理 HTTP 入口。
5. 网关通过原 SDK 访问 `lottery_entries/codes/pools/coupons` 等原业务集合，保留原 entryId 算法与服务端事务；每个用户的同一活动结果与库存继续由原逻辑判定。新建独立的 `lottery_h5_rates` 集合，仅服务器可读写，并为 `expiresAt` 建立 TTL 清理索引。限频采用事务，按用户/动作限频，登录还有全局限频；限频数据库不可用时拒绝请求。
6. HTTP 网关路由将 `/api/bubble-h5/session` 与 `/api/bubble-h5/call` 指向此新函数并透传完整路径。H5 页面、接口应使用有效 HTTPS；设置 `H5_ALLOWED_ORIGINS` 为网页 Origin 精确白名单，禁止通配符。使用平台网关加总请求速率限制；不要记录请求 Authorization、登录 body 或 code2Session URL。
7. `H5_MINIPROGRAM_ENTRY_PAGE=pages/bubble-h5/index` 是活动小程序码的正式入口；需要该页面先发布，且函数具备 `wxacode.getUnlimited` 权限。活动码生成仍由管理员权限控制，前端拿到的是 HTTPS 临时 URL。
8. 测试环境完成微信真机登录、同一用户原页面与 H5 结果一致、双端并发不重复发奖、员工权限、退款/占用状态显示、实物去收银核销和二维码可读性验证后，再设置 `H5_GATEWAY_ENABLED=1`。这是上线步骤说明，本次没有执行。

`node --test tests/gateway*.test.cjs` 只使用本地桩、内存数据和假标识，无真实登录、抽奖或核销。覆盖身份伪造、签名篡改、过期、Origin、输入、禁用开关、越权行为、错误脱敏、限频、原业务事务幂等与物理核销保护。尚未验证微信真机、云函数权限、业务域名、实际线上配置和生产收银联通。
