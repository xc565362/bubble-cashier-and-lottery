# 小程序扫码进入「山野有约」

正式流程：顾客在赛事现场关注小红书 → 工作人员核实 → 工作人员页面生成一次性参与小程序码 → 顾客用微信扫码 → 原生页 `wx.login` → H5 用临时 code 换取短时会话 → 抽头巾 → 中奖后工作人员扫描领取码并核销。

小红书关注情况由工作人员现场核实。这个项目不会伪装为已接入小红书关注查询，也不会在普通浏览器里凭空取得微信 OpenID。

## 接入原生源码

1. 将 `miniprogram/pages/scarf-h5/` 作为新页面复制到要维护的小程序源码中，在 `app.json` 的 `pages` 添加 `pages/scarf-h5/index`。本次没有找到并改写用户的 1.0.5 工程，需要在实际维护工程上完成这一步。
2. 修改该页面 `index.js` 顶部的固定 `H5_URL` 为本活动 HTTPS 地址，必须以 `/` 结尾。不要从 query、scene 或用户输入接收网页目标地址。
3. 此页与后端使用固定 AppID `wx3cfec968f30fb6c1`。配置该小程序的 `web-view` 业务域名，后端换取登录身份的密钥必须属于同一个 AppID。
4. 顾客入口是 `/pages/scarf-h5/index`。工作人员入口可使用 `/pages/scarf-h5/index?return_route=/staff`，权限仍由后台工作人员允许名单决定，入口地址本身不授予权限。
5. 参与小程序码固定 scene 形如 `s_0123456789ABCDEF`；原生页读取 scene，也支持内部页面导航时提供 `inviteCode` 参数。它仅允许 16 位大写十六进制邀请码。
6. 原生页调用 `wx.login` 后把 `wx_code`、`return_route`、`inviteCode` 放在 H5 的 fragment 中。H5 接收后立即移除 URL 里的凭证，用登录 code 调用 `/session`；登录过期需要关闭 H5，从小程序入口重新进入。
7. 页面发布后，后端 `grant` 才能生成正式 `release` 小程序码。发布前应在隔离测试配置中验证，不要把临时演示网页二维码用于实际现场。

## 核销须知

工作人员在 H5「现场工作台」输入或扫描本活动领取码，查询奖品，再确认核销。仅首次成功回执 `alreadyRedeemed:false` 才提示发放；重复请求返回 `alreadyRedeemed:true`，表示不能再发一次。网络异常或回执不确定时应重新查询，并核对现场发放记录。

接入券中心后，新中奖凭证由同一券中心签发，在收银系统“收银”扫码核销，每次放行一件；重复核销不能再次发放。接入前的 legacy 旧领取码仍保留原现场工作台核销方式，没有自动迁移为券中心码。该活动使用独立管理接口，可在收银系统中管理奖品和概率。
